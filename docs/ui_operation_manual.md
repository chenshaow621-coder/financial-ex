# 金融法规页面操作手册

## 1. 适用范围

本手册用于当前 Streamlit 页面：

- 抽取与构建
- 分类概览
- 图谱浏览
- 模型推理演示

对应入口文件：

- `src/business_taxonomy_app.py`


## 2. 页面启动

在项目根目录执行：

```powershell
Set-Location "D:\pythonProject-financial ex"
python -m streamlit run ".\src\business_taxonomy_app.py"
```

如果使用虚拟环境，建议执行：

```powershell
Set-Location "D:\pythonProject-financial ex"
.\venv\Scripts\python.exe -m streamlit run ".\src\business_taxonomy_app.py"
```


## 3. 使用前准备

开始前建议确认以下条件：

- 已准备待处理的法规文档，格式为 `docx`
- 页面使用者已准备可用的 DashScope / Qwen API Key
- 如需导入图谱，Neo4j 服务已启动
- `data/raw/` 目录下已存在法规文档，或准备通过页面上传

当前页面中的文档上传仅支持：

- `docx`

当前页面不支持直接上传：

- `pdf`
- `doc`
- 纯文本粘贴正文


## 4. 页面结构总览

页面包含 4 个页签：

1. `抽取与构建`
2. `分类概览`
3. `图谱浏览`
4. `模型推理演示`

推荐操作顺序：

1. 先在 `抽取与构建` 完成输入、抽取、分类、图谱导入
2. 再在 `分类概览` 检查分类结果
3. 再在 `图谱浏览` 检查场景和召回样本
4. 最后在 `模型推理演示` 做闭环召回和合规查验


## 5. 抽取与构建页

### 5.1 API 配置

页面左侧顶部需要填写：

- `API Key`
- `Base URL`
- `抽取模型`
- `分类/推理模型`

说明：

- `抽取模型` 用于 Phase1/2 和三阶段原子抽取
- `分类/推理模型` 用于业务分类


### 5.2 文档输入方式

当前支持两类输入方式：

1. 上传 `docx`
2. 从 `data/raw/` 中选取已有 `docx`

上传流程：

1. 点击 `上传 docx`
2. 选择一个或多个 `docx`
3. 点击 `导入上传文件`
4. 文件会被保存到 `data/raw/`
5. 页面会自动切换到 `勾选文档` 模式，并把新文件加入可选列表

文档选择方式有两种：

- `勾选文档`
- `关键词筛选`

`勾选文档`：

- 直接从 `data/raw/` 中多选目标文件

`关键词筛选`：

- 输入若干关键词
- 系统按文件名匹配 `data/raw/` 中的文档

说明：

- `每份文档最多处理块数 = 0` 表示不限制
- 该值可用于小范围 smoke test


### 5.3 输出命名

页面允许设置以下输出文件名：

- `Phase1/2 输出`
- `原子抽取输出`
- `业务分类输出`

默认值通常为：

- `phase1_entities_checkpoint.xlsx`
- `legal_atoms_v4_final.xlsx`
- `legal_atoms_business_taxonomy.xlsx`


### 5.4 当前产物盘点

`当前产物盘点` 现在默认只显示：

- 当前页面会话中刚生成的新产物

不会默认显示：

- `data/processed/` 目录中的所有历史项目文件

因此，如果刚打开页面还没执行任何步骤，看到“当前会话尚未生成新产物”是正常现象。


### 5.5 运行按钮说明

#### 运行 Phase1/2

作用：

- 执行实体识别阶段
- 输出阶段性实体结果

输出位置：

- `data/processed/<Phase1/2 输出文件名>`

#### 运行原子抽取

作用：

- 执行 Stage1/2/3 全链路抽取
- 生成原子知识表

输出位置：

- `data/processed/<原子抽取输出文件名>`

#### 运行业务分类

作用：

- 将原子知识映射到业务分类体系
- 同时做场景挂接

输出位置：

- `data/processed/<业务分类输出文件名>`

可选参数：

- `分类批次`
- `分类强制重跑`
- `分类只用启发式`

#### 导入 Neo4j

作用：

- 将业务分类结果导入 Neo4j
- 构建 `BusinessBoard / BusinessCategory / BusinessModule / BusinessScene / BusinessAtom` 图谱

使用前需要填写：

- `Neo4j URI`
- `Neo4j 用户名`
- `Neo4j 密码`


### 5.6 人工核查清单

抽取与构建完成后，进入 `人工核查清单`：

- 先设置典型样本抽样比例和上限，默认按 10% 抽取典型样本。
- 被模型标记为 `is_ambiguous=true` 的原子会单独进入 `模糊判定`。
- 人工逐条给出 `通过` / `存疑` / `明显错误` / `待判断`。
- 页面会计算 `复核完成率` 和 `人工通过复核率`。

`人工通过复核率` 的口径是：

- `通过` 样本数 / 已判定样本数
- 不包含仍为 `待判断` 的样本


## 6. 分类概览页

该页用于快速检查分类结果，例如：

- 各业务分类的覆盖情况
- 场景挂接数量
- 原子分类后的总体分布

适合在“运行业务分类”后立即查看。


## 7. 图谱浏览页

该页用于查看图谱中的结构和召回效果，例如：

- 业务板块
- 业务大类
- 业务模块
- 场景精召回样本
- 模块宽召回样本

适合在“导入 Neo4j”后使用。


## 8. 模型推理演示页

### 8.1 主要用途

用于执行：

- 闭环召回
- 逐轮推理
- 缺口诊断
- 最终合规结论生成

页面提供了预设场景，例如：

- 银行汇票提示付款
- 商业汇票贴现申请
- 银行本票现金兑付与救济


### 8.2 页面输入

主要输入项包括：

- `API Key`
- `Base URL`
- `召回模型`
- `合规问题`
- `业务 query`
- `主体关键词`
- `最多推理轮次`
- `并行数`

`业务 query` 支持多行输入：

- 每行 1 个 query
- 也支持 `query | who` 或 `query<TAB>who`
- 多行 query 会并行执行召回和推理，并按每个 query 展示独立结果


### 8.3 结果查看

页面会展示：

- 最终结论卡
- 审查摘要卡
- 缺口总结卡
- 逐轮推理过程
- 最终证据


## 9. 文档是否参与整条链路

这是当前页面的一个关键行为说明。

### 9.1 已确认会参与的环节

通过页面上传或选中的文档，会参与以下链路：

1. `Phase1/2`
2. `原子抽取`
3. `业务分类`
4. `Neo4j 图谱导入`

也就是说，文档并不是“只参与抽取”。


### 9.2 当前的链路限制

`模型推理演示` 页当前默认读取的是：

- `data/processed/legal_atoms_business_taxonomy.xlsx`

这意味着：

- 如果你的业务分类输出文件名仍然使用默认值 `legal_atoms_business_taxonomy.xlsx`
  - 那么新文档会自然进入后续模型推理链路
- 如果你把分类结果保存成其他文件名
  - 那么 `模型推理演示` 页当前不会自动切换去读取那个新文件

因此，若想让新文档直接进入当前默认推理演示链路，建议：

- 保持 `业务分类输出` 使用默认文件名 `legal_atoms_business_taxonomy.xlsx`


## 10. 推荐操作流程

### 10.1 新文档完整跑一遍

推荐步骤：

1. 打开 `抽取与构建`
2. 上传或选择目标 `docx`
3. 填写 API 配置
4. 点击 `运行 Phase1/2`
5. 点击 `运行原子抽取`
6. 点击 `运行业务分类`
7. 如需图谱，点击 `导入 Neo4j`
8. 打开 `分类概览` 检查结果
9. 打开 `图谱浏览` 检查召回与场景
10. 打开 `模型推理演示` 执行闭环查验


### 10.2 仅更新分类结果

适用场景：

- 原子抽取结果已经存在
- 只想重跑分类

步骤：

1. 确认原子抽取结果文件存在
2. 打开 `抽取与构建`
3. 调整分类参数
4. 点击 `运行业务分类`


### 10.3 仅更新图谱

适用场景：

- 分类结果已经存在
- 只想重新导入 Neo4j

步骤：

1. 确认业务分类结果文件存在
2. 打开 `抽取与构建`
3. 填写 Neo4j 连接参数
4. 点击 `导入 Neo4j`

## 12. 常见问题

### 12.1 页面上看不到刚上传的文档

先检查：

- 是否点击了 `导入上传文件`
- 上传文件是否为 `docx`
- 上传后页面是否已自动刷新


### 12.2 文档关键词没有命中

说明：

- 关键词匹配的是 `data/raw/` 中的文件名，不是正文内容

建议：

- 改用 `勾选文档`
- 或调整关键词，使其更贴近文件名


### 12.3 模型推理演示没有用到新分类结果

先检查：

- 业务分类输出文件名是否仍为 `legal_atoms_business_taxonomy.xlsx`

如果不是默认文件名，当前页面默认不会自动接入该新文件。


### 12.4 当前产物盘点是空的

这是当前设计行为，不是异常。

当前版本的 `当前产物盘点`：

- 只显示本次页面会话中新生成的产物
- 不再默认显示历史项目文件


### 12.5 Neo4j 导入失败

先检查：

- Neo4j 服务是否已启动
- URI、用户名、密码是否正确
- 分类结果文件是否存在


### 12.6 一直出现模型连接错误

先检查：

- API Key 是否正确
- Base URL 是否正确
- 模型名是否可用
- 当前网络是否能访问 DashScope


## 13. 当前建议

在不修改推理演示代码的前提下，推荐当前操作规范为：

- 新文档先通过 `抽取与构建` 完成抽取与分类
- `业务分类输出` 尽量保持默认文件名
- 这样最容易无缝进入 `模型推理演示` 的默认链路
