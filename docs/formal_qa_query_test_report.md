## 观察

1. 当前 fast path 仍然保守：多意图、条件/触发类、实体不足、候选过宽和精确对象不匹配都会回退。
2. Type B 现在会校验问题动作和精确对象；例如“核发/管理开户登记证”“审定本票出票人资格”可命中，但“审核基本存款账户开户登记证”“制定票据凭证格式”因对象抽取或证据范围不足回退。
3. Type C 定义类只接受 `DEF_SCOPE`；“临时存款账户”“农民工工资专用账户”“空头支票”可以给出定义，但混入“只收不付”的定义/条件问题会回退。
4. Type A 的 scope 守门效果更明显：广义开户材料、未声明现金字样、未声明逾期/未获付款等问题不再直接 formal；补齐限定条件后可 formal。
5. 剩余主要短板是召回覆盖与实体归一化：如票据凭证格式制定、银行汇票丧失后请求付款、第三方客户身份识别责任等问题已有图谱证据，但当前实体抽取/对象匹配未形成可形式化回答的约束。
